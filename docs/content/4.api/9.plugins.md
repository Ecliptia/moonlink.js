#title
Plugin Class

#description
The base class for all Moonlink.js plugins. Allows extending and adding functionality without modifying the core code.
<br>
```js
new Plugin(options)
```
::

::alert{type="info" icon="lucide:info"}
Plugins are a powerful way to customize Moonlink.js for your specific needs without modifying the core library.
::

## Overview

::card{icon="lucide:box"}
#title
Properties

#description
Core properties of the Plugin class.
<br>
<h5>Available Properties</h5>

#content
| Property | Type | Description |
| -------- | ---- | ----------- |
| `name` | `string` | Plugin name |
| `version` | `string` | Plugin version |
| `description` | `string?` | Plugin description (optional) |
| `author` | `string?` | Plugin author (optional) |
| `manager` | `Manager` | Manager instance (available after loading) |
::

::card{icon="lucide:settings"}
#title
Configuration Options

#description
Options for configuring a Plugin instance.
<br>
<h5>Plugin Options</h5>

#content
| Option | Type | Default | Description |
| ------ | ---- | ------- | ----------- |
| `name` | `string` | Required | Plugin name |
| `version` | `string` | Required | Plugin version |
| `description` | `string` | `undefined` | Plugin description |
| `author` | `string` | `undefined` | Plugin author |
| `minVersion` | `string` | `undefined` | Required minimum Moonlink.js version |

::alert{type="warning" icon="lucide:alert-triangle"}
The `name` and `version` options are required. Without them, the plugin will not function correctly.
::
::

## Usage Examples

::card{icon="lucide:code"}
#title
Basic Setup

#description
Example of creating and using a plugin.
<br>
<h5>Code Example</h5>

#content
```js
const { Plugin } = require('moonlink.js');

class MyPlugin extends Plugin {
  constructor() {
    super({
      name: 'MyPlugin',
      version: '1.0.0',
      description: 'An example plugin',
      author: 'Your Name'
    });
  }
  
  load(manager) {
    super.load(manager);
    
    // Add functionality to manager
    manager.on('trackStart', (player, track) => {
      console.log(`Playing: ${track.title}`);
    });
  }
  
  unload() {
    // Clean up resources
    super.unload();
  }
}

// Use the plugin
const manager = new Manager({
  nodes: [...],
  plugins: [new MyPlugin()]
});
```

#footer
This example shows basic plugin creation with events.

## Best Practices

::card{icon="lucide:lightbulb"}
#title
Development Guidelines

#description
Best practices for developing plugins.

#content
1. **Resource Cleanup**
   - Always implement the `unload()` method
   - Remove all event listeners
   - Clear intervals and timeouts

2. **Error Handling**
   - Use try/catch in async operations
   - Log errors appropriately
   - Don't let errors break the player

3. **Documentation**
   - Document all options
   - Provide usage examples
   - Maintain an updated README

4. **Compatibility**
   - Check Moonlink.js version
   - Test with different versions
   - Maintain backward compatibility

5. **Performance**
   - Optimize heavy operations
   - Avoid memory leaks
   - Use caching when appropriate

#footer
Following these practices will help create robust and reliable plugins.
